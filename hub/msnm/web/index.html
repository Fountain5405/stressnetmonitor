About

This page is the live side of a monitor for the Monero FCMP++ stressnet, a public test network that is pushed with a heavy, sustained transaction load. The question it is built to answer: what is the minimum hardware that can run a node through that load?

Each monitored node runs a small sidecar next to monerod that reports its RPC, block timing and host load to a hub. Reference nodes define the network tip; every other node is measured against them.

Nodes are listed under arbitrary IDs: who runs a node, and where, is not shown.

Running a node? The newest sidecar is ; nodes with an older one are tagged “sidecar update”. To upgrade, run git pull in your copy of the repo, then sudo ./sidecar/install.sh (your settings are kept). msnm-sidecar --status shows your node's ID on this page.

Logging. The project's own nodes are trying this monerod log setting (from 18 Oct): --log-level 0,blockchain:INFO,txpool:INFO,blockchain.db.lmdb:INFO,perf.blockchain:DEBUG,perf.txpool:DEBUG,perf.ringct:DEBUG,verify:INFO,net.cn:INFO,net:WARNING,net.p2p:WARNING,serialization:WARNING,daemon.rpc:WARNING. On top of level 0's warnings it keeps block and pool events, per-transaction verification timings (perf.*), database timings, peer and sync state changes (net.cn), the reasons transactions are rejected (verify), and warnings from networking, serialization and RPC. It leaves out level 1's line for every P2P message and RPC call: in a test hour those were 80% of level 1's output. Think something is missing? Say so in the feedback thread.

Verify
time the node took to check and add the latest block (--show-time-stats)
RPC
how long the node takes to answer a get_info call, timed on the node itself; wallets and services using a slow node wait this long
Delay
how long after a reference first saw a block this node accepted it
Lag
blocks behind the network tip
Pool
transactions in the node's pool; a node that can't keep up holds fewer
CPU
generation, process and year are looked up from the model name; instruction sets come from the node (crossed out: missing)

Data refreshes every 5 s; charts every minute. Times in UTC. Nodes are listed under arbitrary IDs.
